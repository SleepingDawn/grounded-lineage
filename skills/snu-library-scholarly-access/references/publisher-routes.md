# Retrieval routes by publisher

Pick the first route that applies instead of rediscovering it. Give this table to every reading sub-agent. Rows marked *observed* come from real retrievals (2026-11, a-SiO₂ κ lineage, 4 parallel readers); update them when a route changes.

**What `read_url` accepts.** Only the open-repository allow-list: arXiv, PMC (`pmc.ncbi.nlm.nih.gov`, `www.ncbi.nlm.nih.gov`), Europe PMC, chemRxiv, bioRxiv, medRxiv. Every publisher host (nature.com, frontiersin.org, aps.org, …) returns `not_open_access_host`, even for open-access articles. Fetch those with `download_pdf`, then `read_pdf`.

**Preflight once per investigation, before dispatching readers.** Call `doctor(probe_url=<one paywalled article URL from the reading list>)` (CLI: `scholarly-access-agent doctor --probe <URL>`), preferably a ScienceDirect article or one from the most common subscription publisher on the list. The probe fetches that PDF headlessly into a temporary folder and deletes it at once. `session_probe.session_valid` is `true` (PDF served), `false` (login page: ask the user to renew the SNU session per access-and-auth.md *before* starting the batches) or `null` (inconclusive; `status: "blocked"` means the probe article's publisher runs a bot check, so probe another subscription publisher and plan open-copy fallbacks for that one).

**DOIs.** `download_pdf` accepts `doi:10.x/…`, a bare `10.x/…` or a `doi.org` URL and resolves it to the publisher's article URL without a browser (only the DOI is sent), then follows the publisher's row below.

**Unpaywall before any publisher page.** `https://api.unpaywall.org/v2/<DOI>?email=<generic address>` lists open copies with `version` (`publishedVersion`, `acceptedVersion`, `submittedVersion`) and licence. A `publishedVersion` copy on an open host is the journal text and avoids publisher bot checks; record its host and licence. A host the tools report as `unsupported_domain` is reported to the user, not added.

**`blocked` / `bot_challenge`.** `download_pdf`, `discover_pdfs` and batch downloads report `status: "blocked"`, `reason: "bot_challenge"` when a publisher bot check or bot block explains the failure. Detection uses Cloudflare challenge URL tokens, interstitial titles ("Just a moment...", "잠시만 기다리십시오"), challenge text, the 1000-series block box, and the `cf-mitigated: challenge` header (markers adapted from SleepingDawn/paper_download). Such a check never stops the attempt early. The tool still tries PDF endpoints the server serves without a check, and reports `blocked` only if none works. It never solves or bypasses a check. In a batch, a blocked job does not freeze the other jobs (only `login_required` does). Skipping the preflight lets every Elsevier paper in the batches end at the abstract, which costs both time and evidence level. A loaded article page is not proof of access: ScienceDirect landing pages load without a login wall while the PDF endpoint demands one (*observed*).

| Publisher (host) | Journal version route | When it fails | Notes |
|---|---|---|---|
| APS (journals.aps.org) | `download_pdf("https://journals.aps.org/<journal>/abstract/<DOI>")`; the tool derives `/<journal>/pdf/<DOI>` | Pass the `/<journal>/pdf/<DOI>` URL directly; then arXiv | *Observed*: the article page shows a Cloudflare check ("Just a moment...") to headless browsers, but `/<journal>/pdf/<DOI>` serves the PDF (200), so downloads succeed through the derived endpoint. Before the derivation rule the abstract URL gave `no_pdf_found`. *Observed 2026-11-23*: opening the PDF link or the DOI landing page *as a page* meets the bot check, while fetching `/<journal>/pdf/<DOI>` with the abstract page as source works. `download_pdf` now does this for any APS input — abstract URL, PDF link, `doi:`/`doi.org`/`link.aps.org` — so pass whichever you have |
| Nature portfolio OA (nature.com: npj, Sci. Rep., Nat. Commun.) | `download_pdf(article URL)` → `read_pdf` | PMC copy via `read_url` | *Observed*: `read_url` refuses the host; `download_pdf` works. Supplementary PDFs via `discover_pdfs` |
| Frontiers (frontiersin.org) | `download_pdf(article URL)`; derives `/articles/<DOI>/pdf` | PMC via `read_url` | *Observed*: works |
| PNAS (pnas.org) | PMC via `read_url` (`PMC<id>`), with sections | arXiv for methods missing from the PMC page | *Observed*: pnas.org gave no PDF; PMC worked. PMC pages may omit SI and methods appendices |
| AIP (pubs.aip.org: JAP, JCP, APL) | Go to the arXiv version directly unless the page or figures are needed | `download_pdf` from the article page (often `no_pdf_found`) | *Observed*: `download_pdf` and `discover_pdfs` both gave `no_pdf_found` (not `login_required`); arXiv HTML worked. *Observed 2026-11-23*: article page and DOI landing page `bot_challenge`; article page + explicit `pdf_url` (from Crossref `link`) `download_failed` (403). No working route that day. Many AIP papers are CC-BY: check Unpaywall first (below); a published-version copy in an institutional repository or a CC-BY arXiv replacement carrying the journal reference counts as the journal text once compared |
| ACS (pubs.acs.org: JCTC, JPC) | `download_pdf(article URL)` with SNU session | arXiv / ChemRxiv | *Observed*: HTTP 403 on JCTC once; 2026-11-23 the landing page and PDF link `bot_challenge`, landing + `pdf_url` `download_failed`; arXiv used |
| Elsevier (sciencedirect.com) | Look for an open copy first: HAL by DOI (`https://api.archives-ouvertes.fr/search/?q=doiId_s:"<DOI>"&fl=halId_s,fileMain_s`), institutional repository, arXiv. Otherwise `download_pdf(article URL)` (derives `/pii/<PII>/pdfft`) | Record `RETRIEVAL_FAILED (access restriction)` | *Observed 2026-11-20*: every ScienceDirect PDF answered HTTP 403 from Cloudflare with the 1000-series block box (`CLOUDFLARE_ERROR_1000S`), now reported as `blocked` / `bot_challenge`. Access from the SNU network is IP-based, so the SNU proxy session plays no part and renewing the login cannot help. A visible browser showed the Cloudflare check ("잠시만 기다리십시오"). HAL served 4 of 5 Elsevier papers (author manuscripts or the typeset version). HAL is not on the `read_url` allow-list: fetch `fileMain_s` with the user's permission, then `read_pdf`. Elsevier's own TDM terms also restrict automated downloads |
| Wiley, T&F, IEEE, SAGE, MDPI, PLOS, PeerJ | `download_pdf(article URL)`; the tool derives the byte-serving endpoint | arXiv / repository copy | Derivation rules are in `runtime/pdf.py` |
| Theses and institutional repositories (e.g. iris.sissa.it, hdl.handle.net) | Not reachable by the tools | Ask the user, or record `RETRIEVAL_FAILED (access restriction)` | *Observed*: HTTP 403 from the repository and its CORE mirror |
| `doi.org` links | Never pass a DOI resolver URL | Resolve to the publisher URL first (Crossref or the search result) | `download_pdf` rejects `doi.org` as unsupported |

Record the route actually used in the evidence record (`route`, `version`). A retrieval failure is an access fact, never a reason to exclude a paper.
