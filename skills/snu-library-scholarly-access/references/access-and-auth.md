# SNU access and authentication
Use original publisher URLs and the dedicated profile at `~/.local/share/snu-library-scholarly-access/profile`. Do not use an everyday browser profile. Files are owner-only but not encrypted.

Prefer the journal version of record when one exists: publisher open-access copies and PMC/Europe PMC first, then the SNU subscription route under the conditions below; use preprint repositories only as a fallback (see research-workflow.md, version priority). Use public authorized versions when available: `read_url` and `download_pdf` fetch allow-listed open repositories (arXiv, PMC, Europe PMC, chemRxiv, bioRxiv) directly, without the SNU proxy or session. SNU login provides access, not blanket permission for automated collection or external AI processing. Check applicable publisher/SNU conditions for subscription content: https://lib.snu.ac.kr/find/databases_openaccess/tdm/ . If restricted, seek an authorized public copy or report the limitation. Do not bulk-download or bypass access controls.

On `login_required`, ask the user to run the repository's `scripts/서울대 로그인.command` or `scholarly-access-agent open-url ARTICLE_URL --wait-for-login --headless false` (on Windows add `--browser-channel chrome` or `msedge` if the bundled browser does not open), or to rerun the repository's `install.ps1` / `install.sh`, which renews only what is missing. The command waits for Enter on stdin, so run it in a terminal the user can type into. User signs in directly and presses Enter. Never request or inspect passwords/cookies. Retry once after confirmed renewal. Stop repeated failures or unsupported publishers; do not auto-add domains.

`status: "blocked"` with `reason: "bot_challenge"` means a publisher bot check or bot block (Cloudflare and similar), not a login problem: do not ask the user to sign in again, do not retry in a loop, never try to solve or bypass it; go to the open-copy routes in publisher-routes.md and record the paper as `RETRIEVAL_FAILED (access restriction: bot check)` if none exists. Only `login_required` calls for a session renewal.

MCP/CLI tools: `doctor` (`probe_url` / `--probe URL` checks the session really serves a subscription PDF); `check_url`/`check-url`; `read_url`/`read-url URL [--terms ...|--sections ...]`; `proxy_url`/`proxy-url`; `discover_pdfs`/`discover-pdfs`; `download_pdf`/`download-pdf`; `read_pdf`/`read-pdf PATH --terms TERM ...` or `--pages 3-5`. Routine downloads are headless. The `download_pdf` output includes `output_path`.
